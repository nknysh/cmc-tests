# Self-healing CoinBoard locators

`self-heal-coinboard-locators.mts` is a standalone script (not wired into Playwright — it runs the suite itself as a subprocess) that keeps the CoinBoard page objects (`tests/coinboard/pages/`) working when the app's markup changes:

- Runs `--project=coinboard` (with `SKIP_BTC_PRICE_HEAL`, so no live CMC calls) and inspects the JSON report (`last-run.json` here, gitignored). If everything passed, it exits immediately. Failures are deduped by title and the last attempt wins, so a test that passed on a CI retry doesn't count.
- It heals only when **every** failure is a locator that matches nothing: `element(s) not found`, `resolved to 0 elements`, `toHaveCount` received 0, `strict mode violation`, a detached element, or an action timeout whose locator never resolved. Don't key on `waiting for getBy…`/`waiting for locator`: Playwright logs that on every assertion, so an early version treated a plain text regression as locator breakage and went on to download and run the model. A locator that resolved but saw the wrong content (`unexpected value`, a nonzero `toHaveCount` or `resolved to N elements` mismatch), a failure from the fixture's unexpected-browser-error check, or any other assertion failure is a real regression: the script leaves it alone and exits non-zero, rather than patching locators around it.
- The coinboard `page` fixture attaches a `dom snapshot` to every failing test (`tests/coinboard/domSnapshot.ts`): tags, `data-testid`/`aria-*`/`role`/`id`/`for` attributes and text, long selects trimmed to a few options. A plain ARIA snapshot drops the test ids and `for` attributes some locators use.
- Each failing spec implicates the page objects whose fixtures it uses (`PAGE_OBJECT_FIXTURES`: `comparePage`, `coinPage`). Add a new page object fixture there too, or its failures are left for a human. For each implicated page object, the script sends its source, the errors and one DOM snapshot to a **locally-run** LLM (Qwen2.5-Coder-7B-Instruct, GGUF, via `node-llama-cpp`, through `.agents/shared/localModel.mts`) and asks for the complete corrected file. No API key, no network call to an LLM provider. The model is downloaded (~4.7GB) to `.agents/shared/models/` (gitignored) the first time a heal is attempted, never on a passing run.
- Every local-model call is bounded (`localModel.mts`): `maxTokens` (about twice the page object's size for a fix, 512 for an audit, 4096 by default) and a 30-minute timeout that throws rather than returning a cut-off file. It logs each phase (resolving/downloading, model ready, generating, done) so a slow run isn't mistaken for a hang. The workflow job has `timeout-minutes: 120`.
- Writes the proposed files and re-runs the whole project. Then the shared local-model auditor (`.agents/self-heal-commit-auditor/`, see its `CLAUDE.md`) checks each patch: a patch can pass by coincidence while still changing an assertion or adding a fragile locator. Only if every audit is `PASS` does it commit the patched page objects (`--no-verify`, so the pre-commit review hook is skipped). A failed re-run or any `CRITICAL` audit reverts every patched file and exits non-zero. In CI it scopes the repo owner's git identity to that one commit.
- `.github/workflows/coinboard-tests.yml` runs this on pushes to `main`, on pull requests touching the app or its tests, and on `workflow_dispatch`, wrapped in `allure run` (the coinboard quality gate). It checks out the PR head rather than the merge commit, and its "Push healed locators" step pushes a heal commit to the branch under test (`main` or the PR's branch). A fork's branch can't be pushed to, so there it only notes the fix in the job summary. A `GITHUB_TOKEN` push doesn't trigger another run, so the heal can't loop. CPU-only inference on a standard GitHub-hosted runner is slow (minutes per completion), but it only runs when locators break.
